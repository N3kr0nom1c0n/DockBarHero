# Repository Instructions

## Required Reading

1. Read `PROJECT.md` before broad source exploration.
2. Read only the files needed for the assigned task.

## Project Context Ownership

- The parent orchestrator is the only writer of `PROJECT.md`.
- Workers suggest context updates in their final handoff.
- Record a claim as verified only after the parent confirms it.
- Keep `AGENTS.md` at or below 100 lines.
- Keep `PROJECT.md` at or below 150 lines.

## Working Rules

- Preserve unrelated user changes.
- Keep assignments narrow and avoid duplicate investigation.
- Use canonical commands from `PROJECT.md`.
- Report decisive test output and paths instead of pasting large logs.
- Keep current truth in `PROJECT.md`; use git history for old decisions.

## Verification

- Run checks proportional to the change.
- Do not describe work as complete without fresh verification.
- Update `PROJECT.md` only after the verified milestone is clear.
